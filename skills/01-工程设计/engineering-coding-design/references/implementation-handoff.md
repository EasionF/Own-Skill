# 实施交接格式

## 1. 执行目标

- 本轮要交付什么。
- 哪些能力必须完成。
- 哪些能力明确不做。

## 2. 工作范围

- 需要新增的模块。
- 需要修改的模块。
- 需要保留不动的模块。
- 外部依赖或环境要求。

## 3. 阶段拆分

每个阶段必须包含：

- 目标。
- 文件或模块范围。
- 主要改动。
- 验证方式。
- 完成标准。

推荐阶段：

1. 基础结构与契约。
2. 核心路径实现。
3. 异常、权限、恢复路径。
4. 测试、评测、观测。
5. 迁移、文档、验收。

## 4. 验证计划

- 必跑命令。
- 必测场景。
- 错误路径。
- 兼容性检查。
- 性能或安全检查。
- AI 项目的 eval/golden case。

## 5. 风险控制

- 最容易出错的地方。
- 需要保护的现有行为。
- 需要人工确认的点。
- 回滚或恢复方式。

## 6. 交付格式

最终交付应包含：

- 设计摘要。
- 已完成阶段。
- 代码改动范围。
- 验证结果。
- 未覆盖风险。
- 后续建议。
