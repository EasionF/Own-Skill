# 调试与失败迭代

## 1. 复现

- 获取失败命令。
- 获取输入和环境。
- 获取日志和错误栈。
- 尽量用最小步骤复现。

## 2. 定位

- 确认失败发生层级：编译、类型、运行时、网络、数据库、权限、测试断言、外部依赖。
- 找到最近相关改动。
- 对照现有通过路径。
- 检查配置和环境变量。

## 3. 假设

- 提出一个可验证原因。
- 用代码、日志、测试或最小实验验证。
- 不同时推进多个未经验证的猜测。

## 4. 修复

- 优先修根因。
- 保持改动边界。
- 不用大范围重构掩盖局部问题。
- 添加能防止回归的测试或验证。

## 5. 重新验证

- 先跑最小相关验证。
- 再跑受影响范围更大的验证。
- 如果失败变化，重新定位。
- 如果失败与任务无关，说明残余风险。

## 6. 停止条件

可以停止并报告阻塞的情况：

- 缺少必要凭据或外部服务。
- 环境无法安装或启动。
- 用户改动和任务目标直接冲突。
- 继续修改会越过用户授权边界。
