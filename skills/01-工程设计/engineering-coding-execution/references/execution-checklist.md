# 执行检查表

## 1. 接收输入

- 用户目标。
- 已确认设计。
- 验收标准。
- 相关文件。
- 失败日志。
- 环境约束。

## 2. 建立上下文

- 阅读相关代码。
- 阅读配置。
- 阅读测试。
- 查找现有模式。
- 确认依赖关系。
- 确认入口和调用路径。

## 3. 确认范围

- 本次要改什么。
- 本次不改什么。
- 哪些文件属于目标范围。
- 哪些行为必须保持兼容。
- 哪些风险需要验证。

## 4. 实施

- 按现有风格修改。
- 优先使用现有 helper、类型、接口和模式。
- 避免无关重构。
- 避免重复实现已有能力。
- 保持改动可审查。

## 5. 测试与验证

- 补充或更新测试。
- 运行最接近目标的验证命令。
- 覆盖正常路径。
- 覆盖错误路径。
- 覆盖边界条件。

## 6. 收尾

- 删除自己引入的无用 import。
- 删除自己引入的死代码。
- 删除临时调试输出。
- 保留必要日志和错误说明。
- 汇总验证结果。
