# 改动边界与用户改动保护

## 1. 改动范围

- 只修改实现目标必需的代码。
- 不顺手重构无关文件。
- 不统一格式化整个仓库。
- 不替换无关依赖。
- 不改变用户没有要求的产品行为。

## 2. 用户改动保护

- 允许工作区是 dirty 状态。
- 不回滚不是自己造成的改动。
- 不删除用户文件。
- 不覆盖用户正在编辑的内容。
- 如果用户改动和当前任务冲突，先说明冲突并请求确认。

## 3. 文件操作

- 手工编辑使用 `apply_patch`。
- 避免破坏性命令。
- 避免递归删除或移动，除非目标明确且已确认。
- 生成文件只保留任务需要的产物。

## 4. 抽象控制

- 只有在减少真实复杂度、减少有意义重复或匹配现有模式时才新增抽象。
- 不为假想未来需求添加配置、接口或插件点。
- 不把局部需求扩大成框架级改造。

## 5. 依赖控制

- 优先使用已有依赖。
- 新增依赖必须有明确收益。
- 新增依赖要考虑体积、维护性、安全性、许可证和运行环境。
- 不为了少写少量代码引入重依赖。
