# 验证检查表

## 1. 选择验证方式

按风险选择最接近真实行为的验证：

- 单元测试。
- 集成测试。
- 端到端测试。
- 类型检查。
- lint。
- 构建。
- smoke test。
- 手工 API/CLI 验证。
- 数据迁移验证。
- AI eval/golden case。

## 2. 必测路径

- 正常路径。
- 错误路径。
- 边界输入。
- 权限边界。
- 数据兼容。
- 并发或幂等。
- 外部依赖失败。
- 回滚或恢复路径。

## 3. 验证失败处理

- 保存关键错误信息。
- 定位失败层级。
- 区分代码问题、环境问题、测试问题和数据问题。
- 修复后重新运行相关验证。
- 不把失败验证包装成成功交付。

## 4. 无法验证时

说明：

- 没有运行什么。
- 为什么不能运行。
- 已做的替代验证。
- 剩余风险。

## 5. 交付前检查

- 目标行为已验证。
- 相关错误路径已验证。
- 没有遗留临时调试输出。
- 没有引入无关文件。
- 最终说明包含验证命令和结果。
