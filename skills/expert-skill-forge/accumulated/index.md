# Accumulated · 运行时积累资产索引

> 这个目录**初始为空**，随使用增长。
> 不是设计时写死的，是用这个 skill 锻造过几次 skill 后才长出来的——对应方法论第 5 步"资产体系"。

## ⚠️ 强制声明：这不是可选的"建议沉淀"，是流程的强制最后一步

每次用 expert-skill-forge 锻造完一个 skill 后，**必须**做两件事，否则本次锻造不算完整：

1. **在下方"索引"表里追加一行**（日期 / 锻造的 skill / 领域 / 最大收获）
2. **沉淀至少一个文件**到本目录（锻造记录 / 领域规则 / 踩坑记录 / 验证案例，任选其一即可）

为什么是强制的？因为这是一个反复出现的反模式——**机制设计出来了，但没有被接入执行流程，用完就忘**。如果只是"建议沉淀"，人大概率会跳过：验证完觉得"搞定了"，不会回头补记录，积累层会一直空着。等到下次遇到同类问题，又从零开始，等于这个 skill 白用了。

这跟"生成了字段但没人消费"、"Hook 生成了没人执行"是同一个模式。这个 skill 自己也逃不开这个考验——所以把写入这里变成不能跳过的一步。

---

## 这个目录放什么

每次用 expert-skill-forge 锻造完一个 skill，把以下内容沉淀到这里：

1. **锻造记录**：你锻造了什么 skill、走了哪六步、每步的产出
2. **领域特定规则**：在这个过程中积累的、该领域特有的显性规则（未来同类领域可复用）
3. **踩坑记录**：哪些"纠正方向不对"的症状出现过、正确方向是什么
4. **验证案例**：端到端跑通的案例，作为未来参照

## 文件命名规则

```
[日期]-[锻造的skill名]-[类型].md

示例：
2026-07-08-cc-design-forge-record.md      ← 锻造记录
2026-07-08-cc-design-domain-rules.md      ← 领域特定规则
2026-07-08-cc-design-pitfalls.md          ← 踩坑记录
2026-07-08-cc-design-case-01.md           ← 验证案例
```


## 为什么这个目录重要

没有这个目录，expert-skill-forge 自己就违反了它教的第 5 条原则——"用过一次后留下可复用的沉淀"。

这个目录就是 expert-skill-forge 自己的"personal-asset-index.json"——用得越多，越懂你常踩的坑、常走的弯路、常复用的规则。下次锻造新 skill 时，先翻这里的记录，可能省掉重复摸索。
