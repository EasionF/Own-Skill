# Learning Explanation Guidelines

## 触发场景

在以下情况使用本 skill：

- 用户说“学习一下”“研究一下”“帮我理解”“这个是什么”“我想搞懂”“用费曼学习法”。
- 用户在研究文章、项目、技术方案、架构设计、模型方法、插件机制、记忆系统等复杂内容。
- 用户连续追问“为什么”“怎么做”“完整链路”“核心是什么”，说明需要从概念理解升级到结构化理解。

## 输出方式

默认使用费曼学习法，但不要机械套模板。按用户问题复杂度压缩或展开：

1. 先用一句话说清核心结论。
2. 用普通人能懂的类比解释它到底在解决什么问题。
3. 拆成 3 到 5 个关键步骤或组成部分。
4. 给一个贴近当前语境的例子。
5. 说明容易误解的边界：它不是什么、不能解决什么、什么时候不该用。
6. 最后给 1 到 3 个自检问题，帮助用户判断自己是否真的理解。

## 约束

- 如果用户只要结论，输出压缩版：核心结论、关键原因、下一步。
- 如果用户是在准备给领导汇报，输出要更像“可汇报理解”：概念、价值、链路、风险、落地建议。
- 如果用户的问题本身边界不清，先用 interview 风格确认他到底想理解哪一层，不要直接展开一大堆。
- 不要堆术语。术语必须跟一句白话解释。
- 不要只做摘要。学习类输出必须帮助用户形成“我能复述给别人听”的理解。
